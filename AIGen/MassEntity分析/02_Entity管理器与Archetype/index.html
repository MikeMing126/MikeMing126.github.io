一、FMassEntityManager — 核心管理器

FMassEntityManager 是 MassEntity 框架的核心，负责管理所有实体和 Archetype 的生命周期。它不是 UObject，而是继承自 TSharedFromThis 和 FGCObject 的原生 C++ 结构体。

二、FMassArchetypeData — Archetype 内部结构

定义在 MassArchetypeData.h，这是 MassEntity 数据存储的核心。

2.1 Chunk 内存布局

关键设计：

  • SoA（Structure of Arrays）布局：每种 Fragment 在 Chunk 中有独立的连续数组
  • 固定大小 Chunk：Chunk 大小可配置（默认约 16KB），根据 Fragment 总大小计算每 Chunk 可容纳的实体数
  • 紧凑排列：实体在 Chunk 中紧密排列，删除实体时通过交换末尾元素保持紧凑

2.2 FMassArchetypeFragmentConfig

通过 FragmentConfigs 和 ArrayOffsetWithinChunk，可以在 O(1) 时间内定位任意实体的任意 Fragment 数据。

2.3 FragmentIndexMap

快速查找 Fragment 类型在 FragmentConfigs 数组中的索引，避免每次数据访问都遍历数组。

2.4 EntityMap

将实体的全局索引映射到 Archetype 内的绝对索引（包含 Chunk 索引和 Chunk 内偏移）。

三、Archetype 句柄系统

使用 shared_ptr 确保 Query 缓存的 Archetype 引用在 Archetype 销毁前保持有效。

四、Archetype 迁移

当实体的 Fragment 组合发生变化时（添加/删除 Fragment 或 Tag），实体会从一个 Archetype 迁移到另一个：

关键性能考量：

  • 迁移涉及内存拷贝，但只拷贝共有的 Fragment（新增的 Fragment 使用默认值或初始化回调）
  • 批量迁移比逐个迁移更高效（BatchChangeFragmentCompositionForEntities）
  • 频繁的 Fragment 添加/移除会导致 Archetype 碎片化

五、Archetype 分组（5.6+ 新增）

分组信息存储在 Archetype 级别，同一分组的 Archetype 会被 Query 排序到连续处理，提高缓存局部性。

六、内存管理

6.1 Chunk 分配与回收

  • 新实体添加到 Archetype 的最后一个 Chunk
  • Chunk 满时分配新 Chunk
  • 实体删除时，将 Chunk 末尾实体交换到被删除的位置（保持紧凑）
  • DoEntityCompaction() 可定期整理碎片

6.2 内存大小估算

6.3 SharedFragment 引用计数

  • SharedFragment 通过 FSharedStruct / FConstSharedStruct 内部的 shared_ptr 管理生命周期
  • 当不再有任何 Archetype 引用某个 SharedFragment 值时，该值自动释放
