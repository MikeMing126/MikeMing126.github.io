World Partition 总览

基于 UE 5.7 源码分析 | 面向游戏开发人员

一、什么是 World Partition

World Partition（世界分区）是虚幻引擎从 UE5 开始引入的大世界地图管理与流式加载系统。它将一个完整的大世界地图自动划分为多个网格单元（Cell），在运行时根据玩家位置等流式加载源（Streaming Source）按需加载和卸载这些 Cell，从而实现无缝大世界体验。

核心价值

能力 说明
单一大地图 美术和策划只需在一个统一的世界中工作，无需手动拆分关卡
自动空间分区 引擎根据配置的 Grid 自动将世界空间划分为 Cell
按需流式加载 运行时只加载玩家附近的 Cell，内存占用可控
多人协作 基于 One File Per Actor（OFPA）机制，多人可同时编辑同一地图的不同区域
Data Layer 集成 支持逻辑分层的流式加载控制（如季节切换、任务状态等）
HLOD 支持 自动为远处区域生成 HLOD，降低渲染开销

四、World Partition 的优势与局限

优势

  1. 极大降低大世界制作复杂度 — 美术无需手动切分关卡
  2. 运行时性能可控 — 只加载所需区域，内存友好
  3. 多人协作友好 — OFPA 允许版本控制友好的多人编辑
  4. 灵活的 Grid 配置 — 可配置多层级 Grid，适配不同密度的区域
  5. Data Layer 逻辑分层 — 支持运行时动态启用/禁用内容层
  6. 自动 HLOD — 大幅降低远处场景的渲染开销

局限与注意事项

  1. 学习曲线较陡 — 概念多（Cell、Grid、Data Layer、HLOD、Loader Adapter）
  2. 编辑器性能 — 超大世界在编辑器中可能需要启用 Streaming 才能流畅编辑
  3. 不支持传统关卡流式加载的某些模式 — 如 Level Streaming Volume 的触发式加载
  4. 调试复杂 — Cell 边界、加载优先级、Data Layer 状态等调试需要专门工具
  5. 服务器流式加载需要额外配置 — 默认服务器不流式加载，需要显式启用

五、快速术语表

术语 含义
World Partition 世界分区系统，将大世界自动划分为可流式加载的 Cell
Cell 世界分区的基本单元，包含一组 Actor，对应一个可加载的子关卡
Grid 运行时网格配置，定义 Cell 大小、加载范围等参数
RuntimeHash 运行时空间索引结构，用于快速查找与 Streaming Source 相交的 Cell
StreamingSource 流式加载源，通常是玩家位置，驱动 Cell 的加载/卸载决策
Data Layer 逻辑分层，允许按条件控制 Cell 的加载（如任务系统、季节系统）
HLOD Hierarchical Level of Detail，层次化细节级别，远处区域使用简化模型
OFPA One File Per Actor，每个 Actor 一个文件，支持多人协作编辑
ActorDesc Actor 描述符，轻量级的 Actor 元数据，用于流式生成时避免加载完整 Actor
StreamingPolicy 流式加载策略，决定 Cell 的加载/卸载/激活/去激活的具体实现
LoaderAdapter 加载适配器，用于控制特定 Actor 集合的加载行为
