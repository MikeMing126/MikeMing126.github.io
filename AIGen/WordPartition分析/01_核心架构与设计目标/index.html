01 - 核心架构与设计目标

基于 UE 5.7 源码 Engine/Source/Runtime/Engine/Public/WorldPartition/WorldPartition.h

一、设计目标

World Partition 的设计目标是解决传统关卡系统在大世界游戏开发中的核心痛点：

1.1 传统方案的痛点

痛点 说明
手动关卡拆分 美术需要手动将大世界拆分为多个子关卡，工作量大且易出错
关卡边界问题 子关卡之间的光照、碰撞、LOD 等在边界处容易出现接缝
协作困难 多人编辑同一关卡文件会产生严重的版本控制冲突
内存不可控 传统关卡需要整关卡加载，无法按需加载小区域
流式加载不灵活 Level Streaming Volume 的触发式加载无法适应开放世界的自由移动

1.2 World Partition 的设计目标

  1. 统一的编辑体验 — 整个大世界就是一个地图，无需手动拆分
  2. 自动空间分区 — 引擎根据配置自动将世界划分为可管理的 Cell
  3. 按需流式加载 — 运行时根据 StreamingSource 动态加载/卸载 Cell
  4. 多人协作 — OFPA（One File Per Actor）机制让多人可以同时编辑不同区域
  5. 可扩展性 — 支持 Grid、Data Layer、HLOD 等灵活配置

三、ActorDesc 系统

World Partition 在编辑时不直接操作 Actor 对象，而是使用轻量级的 ActorDesc（Actor 描述符）来描述 Actor 的元数据。

3.1 核心概念

概念 说明
FWorldPartitionActorDesc Actor 的轻量级描述符，包含位置、范围、类、Grid 等信息
UActorDescContainer ActorDesc 的容器，管理一个包中的所有 ActorDesc
UActorDescContainerInstance Container 的实例，支持实例化和容器引用
FActorDescContainerInstanceCollection 多个 ContainerInstance 的集合

3.2 为什么使用 ActorDesc

  1. 性能 — 不需要加载完整 Actor 就能进行空间查询
  2. OFPA 支持 — 每个 Actor 独立存储，ActorDesc 可以快速索引
  3. 流式生成 — 在 GenerateStreaming 阶段只需 ActorDesc 信息即可生成 Cell

六、World Partition 与 UWorld 的关系

关键点：

  • UWorldPartition 存储在 AWorldSettings 上，每个 World 有一个
  • 运行时的流式关卡通过 UWorldPartitionLevelStreamingDynamic 添加到 UWorld::StreamingLevels
  • UWorldPartitionSubsystem 作为世界子系统负责 Tick 驱动和 Streaming Source 管理

七、外部流式对象（External Streaming Object）

外部流式对象用于支持外部 Data Layer 等场景，允许在运行时动态注入 Cell 到 World Partition。

这在以下场景中使用：

  • 外部 Data Layer 的动态加载
  • World Asset Streaming（动态注入关卡流式加载）
  • Content Bundle 系统
