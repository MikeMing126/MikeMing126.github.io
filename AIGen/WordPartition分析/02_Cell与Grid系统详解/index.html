02 - Cell 与 Grid 系统详解

基于 UE 5.7 源码深入分析 Cell 和 Grid 的实现

一、Cell 的概念

Cell（单元）是 World Partition 中流式加载的基本单位。一个 Cell 包含一组空间上相邻的 Actor，在运行时作为一个整体被加载或卸载。每个 Cell 对应一个独立的 Level Package。

二、Grid 的概念

Grid（网格）定义了 Cell 的空间划分方式和加载范围。一个 World Partition 可以配置多个 Grid，每个 Grid 有独立的 Cell 大小和加载范围。

三、Cell 如何分配 Actor

3.1 分配规则

在流式生成阶段，每个 Actor 会被分配到一个 Cell：

  1. 检查 Actor 的 RuntimeGrid 属性 — 决定使用哪个 Grid
  2. 检查 Actor 的 Data Layer — 决定 Cell 关联哪些 Data Layer
  3. 检查 Actor 的位置和范围 — 确定落在哪个 Cell 中
  4. 如果 Actor 太大 — 提升到更大层级的 Cell

3.2 AlwaysLoaded Cell

以下类型的 Actor 会被放入 AlwaysLoaded Cell：

  • 设置了 bIsSpatiallyLoaded = false 的 Actor
  • 全局光照、天空球、大气雾等非空间 Actor
  • 设置为 AlwaysLoaded 的 Actor

3.3 Data Layer Cell

如果 Actor 关联了 Data Layer，则它会被放入关联了相同 Data Layer 的 Cell。Cell 的加载/卸载不仅取决于空间位置，还取决于 Data Layer 的运行时状态。

六、Grid 配置实践建议

6.1 CellSize 选择

场景 建议 CellSize 说明
室内/密集区域 3200 - 6400 小 Cell，精确加载
开放世界 12800 - 25600 标准 Cell，平衡加载频率和内存
超大地图 51200+ 大 Cell，减少加载次数

6.2 LoadingRange 选择

LoadingRange 通常为 CellSize 的 2 倍，确保玩家移动时新 Cell 在旧 Cell 卸载前就已加载完毕。

6.3 多 Grid 配置

建议配置至少两个 Grid：

  • 主 Grid — 标准大小的 Cell，加载大部分游戏内容
  • HLOD Grid — 更大的 Cell，加载 HLOD 模型
