六、性能优化

6.1 Loading Range 优化

  • 不要设置过大的 LoadingRange（内存和加载压力）
  • 根据实际可见距离调整
  • 不同 Grid 可以有不同的 LoadingRange

6.2 Cell Size 优化

  • CellSize 太小 → Cell 数量过多，管理开销大
  • CellSize 太大 → 加载不必要的内容
  • 建议：CellSize = LoadingRange / 2

七、常见问题与解决方案

7.1 Cell 加载卡顿

原因：LoadingRange 过大，Cell 过多

解决方案：

  1. 减小 LoadingRange
  2. 增大 CellSize
  3. 启用 bBlockOnSlowStreaming
  4. 使用异步更新

7.2 Actor 不在预期的 Cell 中

原因：Actor 的 Bounds 超出了 CellSize

解决方案：

  1. 设置 Actor 的 Runtime Grid 到更大 CellSize 的 Grid
  2. 勾选 bIsSpatiallyLoaded = false 使其始终加载

7.3 Data Layer 切换时卡顿

原因：需要加载的 Cell 过多

解决方案：

  1. 预加载（提前将 Data Layer 设为 Loaded 状态）
  2. 使用 Loading Range 预加载范围
  3. 分步激活

7.4 编辑器中性能差

解决方案：

  1. 启用编辑器流式加载（World Settings → Enable Streaming in Editor）
  2. 只加载当前编辑区域
  3. 使用 Minimap 辅助导航

7.5 多人协作冲突

解决方案：

  1. 确保使用 OFPA（World Partition 自动使用）
  2. 不同编辑者编辑不同区域
  3. 使用 Data Layer 分离不同人的工作

十、小结

实践 建议
Grid 配置 根据内容密度选择合适的 CellSize 和 LoadingRange
Data Layer 用于任务、季节、DLC 等逻辑分层
HLOD 必须构建，否则远处性能极差
Streaming Source 自定义传送点、AI 等场景
性能监控 使用 stat Streaming 和调试视图
服务器配置 大世界必须启用服务器流式加载
协作 利用 OFPA 和 Data Layer 分离工作
