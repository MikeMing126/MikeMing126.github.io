1. 为什么需要异步编程

在游戏开发中，异步编程是解决以下问题的关键手段：

问题场景 同步方式的问题 异步解决方案
资源加载 大资源加载阻塞主线程，导致卡顿 后台线程加载，主线程继续渲染
网络请求 等待HTTP响应期间游戏冻结 异步回调，游戏正常运行
文件I/O 读写存档文件阻塞帧 后台线程处理I/O
AI计算 复杂寻路/决策计算耗时 多线程并行计算
大规模运算 仅用单核，浪费多核CPU ParallelFor 并行化

异步编程的核心优势：

  • 保持帧率稳定：耗时操作不在游戏线程执行
  • 充分利用多核CPU：现代CPU通常有6-16核，异步让多核协同工作
  • 提升用户体验：加载过程中可以显示进度条/动画
  • 避免主线程阻塞：游戏逻辑与耗时操作互不干扰

3. 与 Unity 异步编程对比

对于熟悉 Unity 的开发者，以下是 UE5 与 Unity 异步方式的对照：

Unity 方式 UE5 对应方式 说明
StartCoroutine() / yield return FPendingLatentAction / 蓝图 Latent Action 协程式延迟操作
async/await + UniTask TFuture::Then/Next 链式调用 链式异步操作
UniTask.RunOnThreadPool() Async(EAsyncExecution::ThreadPool, ...) 线程池执行
UniTask.ToCoroutine() FPendingLatentAction 子类 与蓝图/协程桥接
Addressables.LoadAssetAsync<T>() FStreamableManager::RequestAsyncLoad() 异步资源加载
Resources.LoadAsync() UAssetManager::LoadAsset() 资源加载（旧API）
C# Task / ValueTask UE::Tasks::Launch() / TFuture<T> 异步任务
C# Thread FRunnableThread::Create() 原始线程创建
JobSystem.BurstCompile ParallelFor + TaskGraph 并行计算
CancellationToken FCancellationToken (新Task系统) 协作式取消

关键差异：

  1. UE5 没有 C++20 协程支持：不像 Unity/C# 可以用 async/await，UE5 C++ 层使用 TFuture/TPromise 和回调实现异步链
  2. UE5 的蓝图异步节点：这是 Unity 没有的概念，通过 UBlueprintAsyncActionBase 为蓝图生成专用的异步节点
  3. UE5 有 TaskGraph 系统：这是一个基于依赖图的任务调度系统，Unity 没有直接对应物
  4. UE5 的 FStreamableManager：类似 Unity Addressables，但集成度更高，是引擎内置的
