七、最佳实践

7.1 行为树设计原则

  1. 宽度优先而非深度优先：尽量让树宽一些而非深一些，减少搜索深度
  2. 高优先级放前面：将最重要的行为放在 Selector 的前面
  3. 合理使用子树：将复杂行为封装为子树（RunBehavior），提高可读性和复用性
  4. 使用服务更新数据：用 Service 周期性更新黑板数据，而非在 Task 中直接更新
  5. 装饰器条件独立：每个装饰器只检查一个条件，使用 DecoratorOps 组合

7.2 性能优化建议

  1. 控制 Tick 频率：Service 的 Interval 不要设得太小（推荐 0.2-0.5s）
  2. 减少黑板观察者：只在必要时使用 FlowAbort 的非 None 模式
  3. 避免深层嵌套：子树嵌套不超过 3 层
  4. 使用 bIgnoreRestartSelf：对于不应被中断的任务设置此标志
  5. 批量黑板操作：多个黑板更新时使用 PauseObserverNotifications

7.3 调试技巧

  1. 使用行为树调试器：在编辑器中实时观察节点执行状态
  2. 重写 GetStaticDescription：为自定义节点提供有意义的描述
  3. 使用 Visual Logger：通过 UE_VLOG 记录行为树决策过程
  4. 检查黑板值：在调试器中查看黑板当前值
  5. 使用 Gameplay Debugger：在运行时通过 ~ 键打开调试菜单查看 AI 状态

八、与 Lyra 示例项目的关联

UE 5.7 的 Lyra 示例项目展示了行为树在实战中的应用。Lyra 中的 AI 主要使用以下模式：

  • 使用 UBTTask_RunBehaviorDynamic 动态切换战斗策略
  • 通过 GameplayTag 管理子树的注入和切换
  • 使用 BTDecorator_CheckGameplayTagsOnActor 基于 GameplayTags 进行条件判断
  • 使用 BTDecorator_TagCooldown 实现基于标签的技能冷却

这种设计模式在大型项目中非常实用，因为它将 AI 行为与 GameplayTag 系统紧密结合，使得策划可以通过配置 Tag 来控制 AI 行为，无需修改代码。
