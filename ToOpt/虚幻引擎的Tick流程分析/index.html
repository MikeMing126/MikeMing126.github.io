虚幻引擎 Tick 流程全解析（基于 UE5.7 源码）

本文基于 UE5.7 本地源码，全面梳理虚幻引擎一帧中所有 Tick 系统的执行流程，涵盖以下核心问题：

  • 引擎主循环如何驱动到 Actor/Component 的 Tick？ 从 FEngineLoop::Tick 到 UWorld::Tick，再到单个 Actor 的 Tick()，完整的调用链是什么？
  • Tick Group 是如何划分的？ 物理前、物理中、物理后、后更新……各阶段的执行顺序和阻塞行为是什么？
  • 除了 Actor/Component，还有哪些独立的 Tick 系统？ Slate/UMG、FTickableGameObject、FTSTicker、渲染线程 Tick 各自的驱动方式和时机。
  • FTickFunction 机制的设计考量是什么？ 为什么 Actor/Component/物理/骨骼动画用 FTickFunction，而 FTickableGameObject、FTSTicker、Slate Widget 不用？
  • 如何在游戏项目中自定义 Tick 控制？ 从全局时间膨胀到选择性时停，涵盖物理、动画、蒙太奇、粒子等各子系统的控制方案。

核心结论：UE5 的 Tick 是一个分层调度系统——FEngineLoop::Tick 驱动 UWorld::Tick，后者通过 FTickTaskManager 按 TickGroup 串行调度 Actor/Component 的 FTickFunction（支持依赖图、并行、时间膨胀），而 Slate/UMG、FTSTicker、渲染线程 Tick 等系统则独立于 World 调度循环之外。理解这一分层结构是实现精确时停控制的基础。

三、Tick Group 详解

TL;DR: Tick Group 定义了 Tick 的执行顺序，从物理前到物理后共 8 个阶段，其中 TG_DuringPhysics 是唯一不阻塞的异步组。

ETickingGroup 枚举（EngineBaseTypes.h:83-110）：

Tick Group 用途 阻塞行为 典型使用者
TG_PrePhysics 主要游戏逻辑 阻塞等待完成 Actor::Tick, MovementComponent
TG_StartPhysics 启动物理引擎 阻塞等待完成 FStartPhysicsTickFunction
TG_DuringPhysics 可与物理并行 不阻塞（异步） 标记 bRunOnAnyThread 的 Component

TG_LastDemotable 最终兜底 阻塞等待完成 被降级的 Tick
TG_NewlySpawned 新生成对象 循环直到无新对象 刚 Spawn 的 Actor

六、FTickFunction 机制的设计考量

TL;DR: FTickFunction 是 UE 为”需要参与 World 帧循环调度”的对象设计的统一框架，核心价值是 TickGroup 排序、依赖图和并行执行。不需要这些能力的系统选择了更轻量的实现。

为什么其他系统不使用 FTickFunction

FTickableGameObject — 不需要 TickGroup 排序，没有排序需求、没有并行需求、不需要 TickGroup。对象之间没有先后依赖关系，都在游戏线程串行执行。它是轻量级的”每帧回调”机制。

FTSTicker — 完全独立于 World，在 Core 模块不依赖 Engine 模块。核心是”延迟后触发”而非”每帧执行”，线程安全，支持回调返回 false 自动移除。

Slate Widget Tick — Tick 与绘制绑定，嵌入在 Paint() 流程中。使用自己的时间源，按控件树层级顺序执行而非 TickGroup。Slate 控件不是 UObject，不关联到 ULevel。

FTickableObjectRenderThread — 在完全不同的线程，需要 FRHICommandListImmediate 上下文，这是 FTickFunction 接口不提供的。

FTickFunction 的核心能力

需要以下任意一个特性时，使用 FTickFunction：

依赖关系（Prerequisite） “我必须在 X 完成之后才能执行”

TaskGraph 集成 作为 Task 加入到 UE 的任务图系统

七、自定义 Tick 控制：时停与时间膨胀方案

TL;DR: UE5 的时间膨胀是分层累乘的（全局 → 单 Actor），物理是全局的不受单 Actor 影响，动画控制最可靠的方式是停止 Component Tick 或直接操作蒙太奇。复杂需求建议自定义 TimeSubsystem。

时间膨胀层级体系

UE5 的时间膨胀是分层累乘的：

层级 属性 作用范围 设置方式
全局 TimeDilation 整个 World UGameplayStatics::SetGlobalTimeDilation()
Sequencer CinematicTimeDilation 整个 World Sequencer Slomo Track
Demo回放 DemoPlayTimeDilation 整个 World 回放系统
单Actor CustomTimeDilation 单个 Actor Actor->CustomTimeDilation = value

时停实现方案对比

方案 A：全局时停 — 简单但影响一切

效果：所有 Actor Tick DeltaTime 变为 0，物理/动画/蒙太奇/Timer 全部停止。RealDeltaSeconds 仍正常传递给网络系统所以网络不会断。

限制：无法让部分 Actor 不受影响；AudioTimeSeconds 不受 TimeDilation 影响。

方案 B：选择性时停 — 通过 CustomTimeDilation

只有被设置的 Actor Tick DeltaTime 为 0，其他 Actor 正常 Tick。但物理是全局的，被冻结 Actor 上的物理体不受影响，需要额外处理（如 PutAllRigidBodiesToSleep() / WakeAllRigidBodies()）。

方案 C：基于 Pause 的精细控制

暂停模式下只有 bTickEvenWhenPaused=true 的对象会 Tick，且走 RunPauseFrame 简化路径。

方案 D：自定义 TimeSubsystem — 最灵活

对于复杂的时停需求（如分区域时停、时停中还能施放技能等），建议创建自定义的时间子系统，完全自主控制每个”时间组”的 DeltaTime，不依赖引擎的 TimeDilation，避免影响动画、物理等底层系统。但需要自己管理所有受影响的子系统。

动画和蒙太奇的时间控制

动画系统通过 AnimInstance 的 Tick 驱动，其 DeltaTime 受全局时间膨胀影响。蒙太奇的更新分两步：Montage_UpdateWeight（更新权重/混合）和 Montage_Advance（推进播放）。

时停对动画的影响：

方案 骨骼动画 蒙太奇 动画蓝图
SetGlobalTimeDilation(0) 停止 停止 停止（DeltaTime=0）
Actor->CustomTimeDilation=0 不一定停止 不一定停止 不一定停止
SetComponentTickEnabled(false) 停止 停止 停止

重要：CustomTimeDilation 影响的是 Actor 的 Tick DeltaTime，但动画由 USkeletalMeshComponent 的 Tick 驱动。如果 AnimInstance 直接从 World 获取 DeltaTime 而非从 Component Tick DeltaTime 获取，CustomTimeDilation 可能不影响动画。

物理的时停控制

物理是全局的，不受单个 Actor 的 CustomTimeDilation 影响。控制方式：

  • 全局时停：SetGlobalTimeDilation(0) → 物理 DeltaSeconds=0 自动停止
  • 手动冻结物理体：SetSimulatePhysics(false) + 清零速度
  • 记录速度并清零：恢复时还原

各系统时停方案推荐

系统 推荐方案 备注
Actor 游戏逻辑 CustomTimeDilation 或自定义 Subsystem 简单场景用 CustomTimeDilation
Component 游戏逻辑 SetComponentTickEnabled 或 Tick Group 控制
物理模拟 全局 TimeDilation=0 或手动冻结物理体 物理是全局的，无法单 Actor 冻结
动画（普通） 全局 TimeDilation 或停止 Component Tick CustomTimeDilation 不一定可靠
蒙太奇 Montage_Stop/Resume 或停止 Component Tick
粒子特效 FXSystem->Tick 受 TimeDilation 影响 或设置 emitter 的 TickMode
UI/HUD 通常不受 TimeDilation 影响 UMG Widget 在 Slate 层 Tick
定时器 TimerManager 受 TimeDilation 影响 时停时定时器不触发
延迟动作 LatentActionManager 受 TimeDilation 影响

各 Tick 系统与 TimeDilation 的关系

Tick 系统 受 TimeDilation 影响 使用的 DeltaTime
Actor Tick (FTickTaskManager) ✅ 是 RealDelta × GlobalDilation × CustomDilation
Component Tick (FTickTaskManager) ✅ 是 同上
FTickableGameObject (World 绑定) ✅ 是 UWorld::Tick 中膨胀后的 DeltaSeconds
FTickableGameObject (nullptr World) ❌ 否 取决于调用处传入值
UMG UserWidget::NativeTick ❌ 否 Slate 自己计算的 DeltaTime
FTSTicker::Tick ❌ 否 FApp::GetDeltaTime()（真实时间）
FTickableObjectRenderThread ❌ 否 渲染线程自己的 DeltaTime
TimerManager::Tick ✅ 是 膨胀后的 DeltaSeconds
FXSystem::Tick ✅ 是 膨胀后的 DeltaSeconds

时停的影响范围：SetGlobalTimeDilation(0) 只影响通过 UWorld::Tick 调度的系统（Actor、Component、TickableGameObject、Timer、FX）。不影响 Slate/UMG、FTSTicker 和渲染线程的 Tick。
