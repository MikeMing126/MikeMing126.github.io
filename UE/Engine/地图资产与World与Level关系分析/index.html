地图资产与World与Level关系分析

发表于2026-04-22|更新于2026-04-22|UE
|总字数:3.8k|阅读时长:15分钟|浏览量:

虚幻引擎地图体系：从资源到运行时的完整解析

  1. 梳理虚幻引擎中 .umap 地图资源、UWorld、ULevel、AWorldSettings 之间的核心关系
  2. 传统 Level Streaming 和 World Partition 两种多关卡加载机制。

一、整体关系图

一个 .umap 地图文件在磁盘上序列化了一个 UWorld，UWorld 在运行时拥有一个 PersistentLevel（ULevel）和零到多个 StreamingLevel（ULevel），每个 ULevel 内部持有该关卡的所有 Actor 以及一个 AWorldSettings Actor 来存储关卡级别的配置。

  • 1 .umap ↔ 1 UWorld（加载关系）
  • 1 UWorld ↔ N ULevel（1 个 PersistentLevel + N 个 StreamingLevel）
  • 1 ULevel ↔ 1 AWorldSettings（关卡配置）
  • ULevel.OwningWorld → UWorld，UWorld.Levels[] → ULevel[]（双向引用）

二、核心概念概览

地图资源（.uasset / .umap）

磁盘上的 .umap 文件本质是一个 UPackage，包含 PKG_ContainsMap 标记，其序列化的顶层对象就是 UWorld。

  • 1 个 .umap = 1 个 UPackage = 1 个 UWorld（内含 1 个 ULevel）
  • 引擎通过 LoadPackage 加载地图时，从 Package 中反序列化出 UWorld 对象

UWorld — “世界”的运行时容器

UWorld 是运行时的”世界”容器，负责整体的 Tick、物理场景、导航系统、网络驱动等跨 Level 的系统。整个游戏运行期间通常只有一个活动的 UWorld 实例。

核心成员 含义
PersistentLevel 指向持久关卡 ULevel*（必须存在）
Levels 当前世界中所有已加载的 ULevel 数组（含持久关卡 + 流式关卡）
StreamingLevels 流式关卡描述器 ULevelStreaming* 数组
AuthorityGameMode 服务器上的 GameMode
GameState 游戏状态

ULevel — 关卡的运行时表示

ULevel 是一个关卡在运行时的表示，持有该关卡的所有 Actor 和一个 AWorldSettings。ULevel 的 Outer 是 UWorld（在 UObject 层级体系中，Level 被 World 拥有），同时通过 OwningWorld 指向运行时所属的 UWorld。

核心成员 含义
Actors 此关卡中的所有 Actor
WorldSettings 指向 AWorldSettings
OwningWorld 指向所属的 UWorld（运行时）
LevelScriptActor 关卡蓝图生成的脚本 Actor

Outer vs OwningWorld：GetOuter() 返回”壳” UWorld（原始 Package 中的 vestigial world），OwningWorld 运行时指向真正的主世界 UWorld。对于流式关卡，引擎用 OwningWorld 来指向实际所属的 UWorld。

AWorldSettings — 关卡级别的配置

每个 ULevel 拥有一个 AWorldSettings，作为该关卡的配置容器，包含物理边界、导航配置、AI 开关、GameMode、重力、KillZ 等环境参数。运行时只有 PersistentLevel 的 WorldSettings 生效，子关卡的 WorldSettings 被忽略（UWorld::GetWorldSettings() 始终返回 PersistentLevel 的配置）。

三、多关卡加载机制：Level Streaming 与 World Partition

核心区别：传统 Level Streaming 从磁盘加载完整的子地图 .umap 文件，提取其中的 ULevel；World Partition 则在运行时动态创建空的 ULevel，再按需将外部 Actor 加载进来。两者的共同点是：运行时只有一个 UWorld，子关卡都作为 ULevel 加入 UWorld::Levels 数组，且只有 PersistentLevel 的 WorldSettings 生效。

传统 Level Streaming

传统 Level Streaming 通过 ULevelStreaming 状态机管理子关卡的加载、可见性切换和卸载。每个子关卡对应一个独立的 .umap 文件。

状态机流转：

加载流程：

  1. ULevelStreaming::RequestLevel() 发起加载，有三条路径：

    • Package 已在内存：直接取出 World->PersistentLevel
    • PIE 模式：DuplicateWorldForPIE
    • 常规路径：LoadPackageAsync() 异步加载

  2. AsyncLevelLoadComplete() 回调中，从 Package 找到 UWorld，取出 World->PersistentLevel（ULevel），通过 SetLoadedLevel() 设置 OwningWorld = 主世界 UWorld

  3. UWorld::AddToWorld() 将 Level 集成到主世界：加入 Levels 数组、注册组件、初始化网络 Actor、路由生命周期

  4. 卸载时 UWorld::RemoveFromWorld() 执行逆操作：注销组件、路由 EndPlay、从 Levels 移除

完整调用链：

核心结论：子关卡的 .umap 文件在磁盘上包含完整的 UWorld，但加载时引擎只提取 World->PersistentLevel（即 ULevel），”壳” UWorld 被遗弃（仅作为 Outer 存在），ULevel 通过 OwningWorld 指向主世界 UWorld。

World Partition

World Partition 是 UE5 引入的新一代关卡加载机制，将一个主地图按空间划分为多个 Cell，运行时根据玩家位置动态加载/卸载。与传统方式最大的不同是：Cell 的 ULevel 是运行时动态创建的，不是从 .umap 文件加载的。

核心类层次：

类名 职责
UWorldPartition 总管理器，挂载在 WorldSettings 上
UWorldPartitionRuntimeHash 运行时空间哈希，决定哪些 Cell 需要加载
UWorldPartitionRuntimeCell 抽象 Cell 基类
UWorldPartitionRuntimeLevelStreamingCell 具体 Cell 实现，持有 LevelStreamingDynamic
UWorldPartitionLevelStreamingDynamic 继承自 ULevelStreamingDynamic，管理实际的 ULevel 创建和 Actor 加载

加载流程：

  1. 初始化：UWorldPartition::Initialize 创建 RuntimeHash，生成所有 Cell 对象
  2. 每帧更新：UWorldPartitionSubsystem::Tick 收集 Streaming Sources（玩家位置等），通过空间哈希查询计算哪些 Cell 需要加载/卸载
  3. Cell 加载：调用 Cell->Load() → LevelStreamingDynamic->Load()，将 LevelStreaming 加入世界的 StreamingLevels
  4. 创建 ULevel：CreateEmptyLevelForRuntimeCell() 通过 UWorld::CreateWorld() 动态创建一个全新的 UWorld + ULevel + WorldSettings（这是与传统方式最本质的区别）
  5. 加载 Actor：FWorldPartitionLevelHelper::LoadActors() 异步加载外部 Actor 包并移入 Cell Level
  6. 激活：Activate() 设置 SetShouldBeVisible(true)，引擎随后通过 AddToWorld() 将 Level 加入主世界

完整调用链：

四、详细解析

4.1 地图资源与 Package 加载

地图在磁盘上是一个 .umap 文件，本质是一个 UPackage。Package 中包含 PKG_ContainsMap 标记，其序列化的顶层对象就是 UWorld。

  • .umap 是持久化层，UWorld 是运行时从 Package 加载出来的第一个对象
  • 引擎通过 LoadPackage 加载地图时，从 Package 中反序列化出 UWorld 对象

4.2 UWorld 核心成员详解

核心成员 含义
PersistentLevel 指向持久关卡 ULevel*（必须存在）
Levels 当前世界中所有已加载的 ULevel 数组（含持久关卡 + 流式关卡）
StreamingLevels 流式关卡描述器 ULevelStreaming* 数组
AuthorityGameMode 服务器上的 GameMode
GameState 游戏状态
WorldType 世界类型（Game / Editor / PIE 等）

核心职责：负责整体的 Tick、物理场景（PhysicsScene）、导航系统（NavigationSystem）、AI 系统（AISystem）、网络驱动等跨 Level 的系统。

关键关系：

  • 一个 UWorld 拥有一个 PersistentLevel（必须存在）
  • 一个 UWorld 可以包含多个 ULevel（通过 Levels 数组，实现关卡流式加载）
  • 整个游戏运行期间通常只有一个活动的 UWorld 实例

4.3 ULevel 核心成员详解

源码注释明确说明：

Every Level has a World as its Outer, however, when a Level has been streamed in the OwningWorld represents the World that it is a part of.

核心成员 含义
Actors 此关卡中的所有 Actor
WorldSettings 指向 AWorldSettings
OwningWorld 指向所属的 UWorld（运行时）
LevelScriptActor 关卡蓝图生成的脚本 Actor
Model BSP 模型数据

Outer vs OwningWorld 的区别：

  • GetOuter() → 返回”壳” UWorld（原始 Package 中的，被称为 “vestigial world”）
  • OwningWorld → 运行时指向真正的主世界 UWorld

对于流式关卡，GetOuter() 返回的是一个”遗迹 World”（vestigial world），所以引擎用 OwningWorld 来指向实际所属的 UWorld。

4.4 AWorldSettings 的生效机制

AWorldSettings 是一个 Actor（继承自 AInfo → AActor），它是每个 Level 的配置容器，包含预计算可见性设置、物理世界边界检查开关、导航系统配置、AI 系统开关、光照构建参数、World Partition / 资源合成等高级设置、DefaultGameMode、重力、KillZ 等环境参数。

每个 ULevel 拥有恰好一个 AWorldSettings（通过 ULevel::WorldSettings 成员引用）。在 PostLoad 时，如果 WorldSettings 为空，会自动从 Actors 数组的第 0 个元素获取：

ULevel::GetWorldSettings() vs UWorld::GetWorldSettings()

这是理解子关卡配置的关键区别：

ULevel::GetWorldSettings() — 直接返回本关卡的 WorldSettings：

任何关卡（包括流送子关卡）调用此方法，返回的都是该关卡自己的 AWorldSettings。

UWorld::GetWorldSettings() — 始终返回 PersistentLevel 的 WorldSettings：

所有全局系统（导航、AI、物理、GameMode 等）都通过 UWorld::GetWorldSettings() 获取配置，所以子关卡的 WorldSettings 完全被忽略。

IsPersistentLevel() 判断

持久关卡 vs 流送关卡对照表

行为 持久关卡 (Persistent Level) 流送子关卡 (Streaming Level)
是否有独立的 AWorldSettings 有，存储在 ULevel::WorldSettings 有，每个 .umap 都有自己的
ULevel::GetWorldSettings() 返回自己的 WorldSettings 返回自己的 WorldSettings
UWorld::GetWorldSettings() 返回这个关卡的 WorldSettings 不会返回子关卡的，仍返回持久关卡的
WorldSettings 的实际作用 控制整个 World 的全局设置（GameMode、导航、HLOD 等） 主要用于序列化/编辑器中子关卡的独立配置，运行时被忽略
IsPersistentLevel() true false
CheckForErrors() 作为”权威”WorldSettings 通过检查 被标记为 “Duplicate level info” 警告
Navigation 构建全局导航网格 动态注入到全局导航系统中
GameMode 决定本局游戏的规则逻辑 子关卡中的 GameMode 设置无效
KillZ 定义玩家被消除的高度 无效
重力 定义全局重力 无效

为什么子关卡还需要 WorldSettings？

  1. 编辑器独立编辑：子关卡可以独立打开编辑，此时它作为 PersistentLevel，WorldSettings 生效
  2. 序列化需要：ULevel::WorldSettings 是 UPROPERTY()，保存时需要序列化
  3. ULevel::GetWorldSettings() 直接返回自己的，某些局部逻辑会用到
  4. World Partition Cell：CreateWorld() 自动创建，但被禁用网络复制

4.5 传统 Level Streaming 源码级流程

ULevelStreaming 核心成员

ULevelStreaming 是一个抽象基类（UCLASS(abstract)），外层对象（Outer）必须是 UWorld（Within=World）。

RequestLevel — 从 Package 加载 ULevel

三条加载路径：

路径 1：Package 已在内存中（同步复用）

路径 2：PIE 模式下的 World 复制

路径 3：异步加载（最常见路径）

AsyncLevelLoadComplete — 异步加载完成回调

核心要点：从 Package 中找到的始终是 UWorld，然后取 World->PersistentLevel 作为实际的 ULevel 对象。

SetLoadedLevel — 设置已加载关卡

UWorld::AddToWorld — 将 Level 加入世界

UWorld::RemoveFromWorld — 将 Level 从世界移除

核心类层次结构

  4. RuntimeHash->GenerateStreaming() 创建所有的 UWorldPartitionRuntimeLevelStreamingCell 对象

    • SetCellStateToLoaded → 调用 Cell->Load()
    • SetCellStateToActivated → 调用 Cell->Activate()
    • SetCellsStateToUnloaded → 调用 Cell->Unload()

World Partition 的 WorldSettings 处理

  • 每个 Cell 创建的 ULevel 都会创建自己的 UWorld 和 WorldSettings（通过 UWorld::CreateWorld 自动创建）
  • Cell 的 WorldSettings 不会参与网络复制（被 FSetActorReplicates 禁用）
  • Cell 的 WorldSettings 是默认的，不是主世界的 WorldSettings
  • 主世界的 WorldSettings 仅存在于 PersistentLevel 中，Cell Level 不共享
  • 在嵌入模式下，子关卡中的非 OFPA Actor 会被丢弃，AWorldSettings 属于非 OFPA Actor，子关卡的 WorldSettings 在运行时根本不存在

五、开发实践建议

  1. 全局配置集中化：始终在 Persistent Level 的 World Settings 面板中设置重力、KillZ 和 GameMode
  2. 避免子关卡逻辑依赖：不要在子关卡的 AWorldSettings 中写任何逻辑或存储关键数据，因为在 World Partition 下它们可能被丢弃
  3. 局部物理覆盖：如果希望不同区域有不同重力，不要通过 World Settings，而应使用 Physics Volume 来局部覆盖
  4. 子关卡只是 Actor 的搬运工，主关卡才是世界的决策者
